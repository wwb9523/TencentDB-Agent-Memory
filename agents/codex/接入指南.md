# 本机 Codex 接入团队 Memory Proxy（备选方案）

> 推荐方案已改为 [Hooks + MCP + Skill 插件接入](../../plugins/tdai-memory/README.md)，保留用户自己的模型 provider。本文仅保留为模型代理接入的备选说明；其中历史核查状态不代表插件部署状态。

适用对象：使用本机 Codex CLI 或 Codex 桌面应用的团队成员。本文采用公网直连，不使用 SSH 隧道，也不要求成员在服务器上运行 Codex。

核查日期：2026-09-14。配置参数已参考 OpenAI 官方文档，本机核查版本为 `codex-cli 0.149.1`；不同客户端版本的界面可能不同。

## 1. 接入后发生什么

```text
本机 Codex（读取文件、修改代码、执行命令）
  |
  | 模型请求 / 按需调用记忆工具
  v
远程 Memory Proxy
  |-- 向请求加入团队记忆、Skill 和已绑定的上下文
  |-- 将对话记录交给 Memory Core，供后续提炼
  v
模型上游（当前为 newapi.uhubdata.com）
```

Codex 和项目仍在本机。改变的是模型请求经过的服务，以及可读取、积累的远程记忆。对话及请求中携带的代码、工具结果等内容会经过远程 Proxy，并按服务端配置记录；不是只上传一句记忆摘要。

多层记忆的使用方式：L3 长期画像和 L2 场景索引注入上下文；L2 正文、L1 原子记忆及 L0 原始对话通过注入的工具按需检索。提炼是异步过程，不能假设刚说的一句话立刻出现在所有层级。

## 2. 团队接入参数与当前状态

## 3. 管理员一次性准备

本节涉及服务器修改，应由管理员在确认变更及重启时段后执行。本文编写过程中未实施这些修改。

### 3.1 网络、账号和记忆归属

1. 允许成员或公司出口 IP 访问服务器 TCP `8096`。Proxy 已监听该端口，不需要为了模型和记忆接入另行开放 Core 的 `8420`。
2. 为每位成员准备业务用户和独立 `user_key`，将用户加入对应 Team，并准备可选择的 Agent / Task。通过团队认可的私密方式分发 Key。
3. 告知成员应该选择哪个 Team、Agent 和 Task。是否共享 OpenClaw 或其他成员的记忆取决于 Agent 绑定及资产权限，不能仅凭使用同一个 Proxy 地址判断。
4. 如成员需要浏览管理面板，另行提供 `8125` 或其反向代理入口；这不是 Codex 模型接入的必需端口。

### 3.2 修正工具对外地址

服务器部署目录：

```text
/root/projects/TencentDB-Agent-Memory/deploy/global-images
```

生效配置为该目录下的 `.proxy-config/config.yaml`。在现有 `injection` 段内增加 `externalGatewayUrl`，保留其余字段：

```yaml
injection:
  enabled: true
  externalGatewayUrl: "http://95.40.122.137:8096"
  injectors:
    - skill
    - knowledge
    - tdai-memory
```

这里填写 **Proxy 根地址**，不要加 `/codex/default`、`/v1` 或 `/responses`。生成的记忆检索地址应为 `http://95.40.122.137:8096/memory-bridge/v3/...`，Skill 地址应为 `http://95.40.122.137:8096/skill-bridge/v3/skill/...`。

**不要只改生成后的 YAML。** `start-proxy.sh` 每次启动都会覆盖它。推荐按以下方式持久化：

1. 备份 `.env`、`start-proxy.sh` 和 `.proxy-config/config.yaml`，记录原有配置及容器镜像版本。
2. 在 `.env` 增加 `PROXY_EXTERNAL_GATEWAY_URL=http://95.40.122.137:8096`。
3. 编辑 `start-proxy.sh` 中生成 YAML 的模板，在现有 `injection:` 的 `enabled:` 下增加：

   ```yaml
   externalGatewayUrl: "${PROXY_EXTERNAL_GATEWAY_URL}"
   ```

4. 确认新变量能被脚本加载后，在部署目录执行 `./start-proxy.sh`，重新生成配置并重建 Proxy 容器。此操作会中断正在经过 Proxy 的请求，应安排空闲时段；无需重启 Core 和 Hub。
5. 检查生成后的 YAML 已包含正确的公网地址，并确认 Proxy 健康：

   ```bash
   curl --fail --silent --show-error http://127.0.0.1:8096/health
   docker logs --tail 200 tdai-proxy 2>&1 | grep 'proxyBaseUrl'
   ```

6. 在新建的 Codex 会话中按第 7 节验证工具 URL 和检索。原有客户端也应验证一次；服务器上的 OpenClaw 必须同样能访问这个公网地址。若服务器自身访问公网 IP 受限，管理员应先解决统一入口的可达性。

这项设置覆盖记忆和 Skill 工具。若还要使用 Wiki / CodeGraph，其资源里的 `service_url` 需另行保证成员可访问；不能认为修改 `externalGatewayUrl` 会自动修复所有知识库地址。

## 4. 成员检查网络并备份配置

以下命令以 macOS / Linux 为例；Windows 用户可在 WSL 中按 CLI 步骤操作。

```bash
codex --version
curl --connect-timeout 5 --max-time 10 --fail --silent --show-error \
  http://95.40.122.137:8096/health
```

预期返回 JSON，包含 `"status":"ok"`。超时请让管理员核对安全组来源 IP，也检查本机 VPN / 代理；公司和家庭网络的出口 IP 可能不同。

Codex 用户配置通常为 `~/.codex/config.toml`；设置了 `CODEX_HOME` 时，路径为 `$CODEX_HOME/config.toml`。先备份已有配置：

```bash
codex_config_dir="${CODEX_HOME:-$HOME/.codex}"
mkdir -p "$codex_config_dir"
if [ -f "$codex_config_dir/config.toml" ]; then
  cp -p "$codex_config_dir/config.toml" \
    "$codex_config_dir/config.toml.before-memory-$(date +%Y%m%d-%H%M%S)"
fi
```

后续编辑的是**用户级**配置，不是项目里的 `.codex/config.toml`。保留原有 provider、MCP、项目、权限等配置；不要用本文片段覆盖整份文件，也不要重复声明同名 TOML 表。

## 5. Codex CLI：单独选择 Memory Proxy

### 5.1 添加 provider

在用户级 `config.toml` 增加以下完整表，原有顶层 `model_provider` 和 `model` 暂时不改：

```toml
[model_providers.tdai-memory]
name = "Team Memory Proxy"
base_url = "http://95.40.122.137:8096/codex/default"
wire_api = "responses"
env_key = "TDAI_MEMORY_USER_KEY"
requires_openai_auth = false
supports_websockets = false
request_max_retries = 2
stream_max_retries = 3
stream_idle_timeout_ms = 300000
```

- `env_key` 是环境变量名，不是 Key 本身。
- `requires_openai_auth = false` 使用 Memory Hub 凭证，不借用已有 OpenAI 登录。
- 当前 Proxy 使用 HTTP POST / SSE，显式关闭 Responses WebSocket 传输。
- 不需要配置固定 `x-conversation-id`，由 Codex 提供会话标识。
- 不需要安装 OpenClaw 插件或新增记忆 MCP。

### 5.2 输入个人 Key 并启动

在目标项目目录执行下面的命令。Key 通过终端隐藏输入，不回显，也不写入这条命令的 shell 历史：

```bash
bash -c '
  read -r -s -p "Memory Hub user_key: " TDAI_MEMORY_USER_KEY
  printf "\n"
  export TDAI_MEMORY_USER_KEY
  exec codex -c "model_provider=\"tdai-memory\"" \
    -m gpt-6-astra -c "model_reasoning_effort=\"high\""
'
```

先启动交互界面，**不要在启动命令末尾附带首条问题**。按第 7 节切换 Plan 模式，再发送第一条消息。不建议用 `codex exec` 做首次交互式绑定。

上述 `-c` 和 `-m` 只覆盖这次启动。退出后正常运行 `codex`，仍采用原有默认 provider。凭证环境变量也只在这次启动的进程及其子进程中存在。

本文采用启动参数单独选 provider，不依赖不同 Codex 版本间有差异的 profile 文件格式。

## 6. Codex 桌面应用：切换用户级默认 provider

CLI 的启动参数不会自动切换已经运行的桌面应用。桌面端需要单独调整用户级配置，并重启应用、新建本地任务。

1. 完成第 4 节备份及第 5.1 节 provider 配置。
2. 处理桌面应用的凭证：从 Dock / Finder 启动的 macOS 应用通常不会继承终端中临时设置的环境变量。团队已有可靠的应用环境变量注入方式时，继续使用 `env_key`；否则可采用下面的直接凭证方式。
3. 在**现有** `[model_providers.tdai-memory]` 表内删除 `env_key` 行，替换为：

   ```toml
   experimental_bearer_token = "REPLACE_WITH_YOUR_PERSONAL_MEMORY_USER_KEY"
   ```

   用本人的 `sk-mem-...` 替换占位符，不要同时保留两种凭证来源。此方式是将凭证明文保存在个人配置中，官方优先推荐 `env_key`；不要把填过 Key 的配置提交仓库或发给同事。macOS / Linux 可执行 `chmod 600 "${CODEX_HOME:-$HOME/.codex}/config.toml"` 限制访问，备份文件也应妥善保存。

4. 修改文件顶部已有的顶层字段；缺少时添加在第一个 `[表名]` **之前**：

   ```toml
   model_provider = "tdai-memory"
   model = "gpt-6-astra"
   model_reasoning_effort = "high"
   ```

   不要把这些字段放到 provider 表、MCP 表或文件末尾的其他表内；已有同名字段直接修改，不能重复添加。

5. 完全退出并重新打开桌面应用，新建**本地**任务，确认所用模型。首次消息前进入 Plan 模式，按下一节完成绑定。

这会改变使用该用户配置的客户端默认 provider，包括随后普通启动的 CLI。已经创建的任务可能保留原 provider / 会话状态，应使用新任务验收。如果当前客户端受管理员策略限制或不支持这个自定义 provider，以客户端提示为准，先联系管理员；本文尚未对所有桌面版本完成实测。

## 7. 首次绑定与验收

### 7.1 初始化会话

1. 在新会话中，发送第一条消息前切换到 **Plan 模式**。CLI 常用 `Shift+Tab` 切换，以界面实际显示为准；桌面端使用当前版本的模式选择入口。
2. 发送一条普通消息，例如：`请开始本次项目任务。`
3. 在 Proxy 返回的交互表单中确认关联团队资产，按提示选择管理员指定的 Team、Agent、Task。不要选择跳过；如界面提供无 Task 选项且符合团队要求，可按实际情况选择。
4. 完成绑定后，可以切回普通执行模式继续工作。

如果初始化时出现 `request_user_input is unavailable in Default mode`，本项目会将该会话标记为 bypass，后续可聊天但不注入团队资产。**这不表示 Codex 普通模式永远不能使用记忆**，限制发生在交互绑定阶段。

恢复方式：优先新建会话，在首条消息前进入 Plan 模式；也可在已切换到 Plan 模式的会话发送 `mem:session-reset` 重新绑定。对已经 bypass 的会话，仅切换模式并继续聊天不足以证明恢复成功。

### 7.2 分三步验收

| 验收项 | 操作 | 成功依据 |
| --- | --- | --- |
| 网络 | 请求 `/health` | HTTP 200，`status` 为 `ok` |
| 绑定与模型 | 完成表单，发送普通问题；再发送 `mem:sync` | 模型正常回答，同步命令未提示“未绑定团队资产” |
| 记忆检索 | 要求 Codex 使用已注入的 TDAI 工具查找一条管理员提供的已知记忆 | 看到实际工具调用，请求目标为公网 Proxy，HTTP / 业务返回成功，内容与已知记忆相符 |

记忆检索提示示例：

```text
请使用已注入的 TDAI 记忆工具，检索管理员提供的测试记忆关键词。
请实际执行查询，说明命中的记忆内容及来源；不要只依据当前聊天内容回答。
```

记忆工具通过 Codex 的命令执行能力调用 Proxy。需要让当前执行环境能访问 `95.40.122.137:8096`；遇到网络权限提示，按团队策略批准所需访问，不必为了接入关闭全部沙箱或审批。

若工具 URL 仍是 `172.19.0.4`、`memory-core` 等内网地址，联系管理员检查第 3 节，并在配置生效后新建会话。若没有预置记忆，返回空结果可以说明接口可用，但不能证明跨会话回忆有效。

### 7.3 验证记忆积累

在专门的测试 Agent / Task 中进行一段不含敏感信息的真实工作对话，由管理员在面板确认 L0 记录及后续记忆生成状态。等待服务端提炼完成后，新建会话并绑定同一个记忆归属，再查询该信息。

不要把模型声称“已经记住”作为成功依据；以实际记录、检索返回及对应的生成状态为准。接入不会自动导入本机以前的聊天历史，历史导入属于另一个操作。

## 8. 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `/health` 超时 | 安全组来源 IP、本机或公司防火墙、VPN / 代理、Proxy 监听状态 |
| HTTP 401 / `missing user_key` | 是否填了业务用户 Key；CLI 环境变量是否传入；桌面进程是否拿到凭证；不要使用供应商 Key |
| 找不到 Team / Agent / Task | 由管理员核对业务用户的团队成员关系和资源权限 |
| 可以聊天，但没有记忆 | 核对是否完成绑定、是否 bypass、Agent 是否正确、工具地址是否可达 |
| 工具命中 Docker 内网地址 | 管理员设置 `injection.externalGatewayUrl`、持久化并重启 Proxy；成员新建会话 |
| 普通终端能联网，Codex 工具不能 | 检查工具执行沙箱的网络权限及执行位置；两者网络环境可能不同 |
| 模型不可用、上游 401 / 403 | 管理员检查服务器上游 Key、模型授权和实例级路由；不要把本人的供应商 Key 替换进 Memory Hub Key 的位置 |
| 404 或协议错误 | `base_url` 应到 `/codex/default` 为止，不能自行追加 `/responses`；使用 `wire_api = "responses"` |
| WebSocket 连接失败 | 确认当前生效 provider 的 `supports_websockets = false`，并重启客户端新建任务 |
| Wiki / CodeGraph 工具失败 | 单独检查知识资源 `service_url`；它不由记忆工具 URL 设置统一覆盖 |
| 看不到其他成员或 OpenClaw 的记忆 | 检查绑定的 Agent、共享或导入资产以及权限；同地址不代表所有人共享全部记忆 |

报障时提供客户端版本、时间、失败阶段、HTTP 状态及脱敏后的错误信息；不要提供完整 Key、未脱敏请求头或包含凭证的配置文件。

## 9. 回退到原来的连接

- **只按 CLI 步骤试用：** 退出当前会话，不带 Memory Proxy 启动参数重新运行 `codex`。原有顶层配置未改变，无需恢复整份文件。
- **桌面端或已修改默认 provider：** 把顶层 `model_provider`、`model` 和 `model_reasoning_effort` 恢复为备份中的原值，完全退出应用后重开并新建任务。只恢复本次修改的字段，避免覆盖接入后新增的其他配置。
- 不再使用时删除新加的 `tdai-memory` provider 和相关本地凭证；如需停用 Key，由管理员执行。
- 回退模型连接不会删除服务端已经保存的记忆；删除记忆需另行按团队流程处理。
